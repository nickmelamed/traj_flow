# TrajFlow

A portfolio trajectory-prediction pipeline on nuScenes mini, for autonomy and
prediction engineering interviews. It compares classical baselines
(constant velocity, constant acceleration, XGBoost) with a small transformer
and an LSTM, and runs a human-in-the-loop loop that flags uncertain
predictions, collects corrections in Streamlit, and fine-tunes a second time.
Good here means honestly measured, including results where the model loses.
Nothing is tuned for SOTA.

The full design lives in docs/SPEC.md (sections 0 to 7 match the original
phase plan). Read the relevant section before changing anything it covers.
Current status and next steps are in PROGRESS.md. Design decisions and their
reasons are in docs/DECISIONS.md.

## Non-negotiable rules

1. Splits are by scene. No scene appears in two of train, val and test. TEST
   is the official nuScenes mini_val list (`build_scene_splits`).
2. HITL flagging and corrections use hard TRAIN examples only. Corrected labels
   never enter any split used for final evaluation.
3. Report every metric as measured. Never round, cherry-pick, drop a row, or
   edit `results/metrics_comparison.md` by hand. Rows are written only by
   `log_metrics`. A losing model stays in the table.
4. Every model, round and ablation is evaluated on the same test parquet.
   Model selection uses val minADE only.
5. Numbers in README.md must come from `results/metrics_comparison.md` or a
   generated artifact. Never type a result from memory.
6. Do not add absolute global heading as a feature in a learned model. It
   leaks scene orientation (D5 in docs/DECISIONS.md).
7. Reported results are the mini run. Do not overwrite mini artifacts with a
   scale-up run. The local `data/processed/`, `corrections/` and
   `artifacts/flagged.parquet` currently come from a scale-up run, and the
   mini copies are in `backups/mini/`. Do not train or evaluate against a mix.
8. Never weaken a test, lint rule, or check to make it pass.
9. Ask before changing anything in `.claude/protected-paths`, the evaluation
   design, dependencies, CI, or hooks.

## Commands

```bash
python -m pytest -q                         # 66 tests, about 3s, synthetic data
python3 scripts/agent/check_style.py .      # style check (the Stop-hook gate)
make agent-check                            # lint, types, fast tests, style
make numbers                                # README numbers vs generated sources
```

The venv is `traj/` (Python 3.11, `pip install -e ".[dev]"`).

## Where things live

- `src/trajflow/`: library code. `data/`, `models/`, `evaluation/`, `hitl/`,
  `viz/`. Paths are defined in `paths.py`.
- `tests/`: unit tests on small synthetic fixtures, no real data.
- `results/metrics_comparison.md`: the results table. `results/figures/`.
- `data/SCHEMA.md`: parquet schema, generated by `trajflow-preprocess`.
- `.claude/rules/`: path-scoped rules. `.claude/skills/`: repo procedures.

## Repo-specific gotchas

- Import xgboost before torch, and set `KMP_DUPLICATE_LIB_OK` and
  `OMP_NUM_THREADS` before either. Both bundle libomp and hang on this Mac.
- nuScenes needs a manual account and licence click-through. If the data is
  missing, stop and tell the owner. Do not try to script around it.
- Check the installed nuscenes-devkit source for signatures. Do not guess.
- Keep models small and CPU-friendly. No distributed training.
- Do not download full nuScenes without being asked.

## How to work here

- Plan before multi-file changes and wait for approval when a task spans
  several modules or touches the spec.
- A task is done when the Stop hook's checks pass. Show the commands and
  their output.
- Commit in small atomic Conventional Commits (`type(scope): subject`), with
  code and its tests together.
- Run `git commit` only when the owner asks, and wrap it in `timeout 40`.
  SSH signing once hung in agent sessions. If it hangs, give the owner the
  message to commit.
- You may branch locally. Ask before pushing, opening or merging pull requests,
  tagging, or changing dependencies.
- If you repeat a multi-step procedure, propose a skill for it in
  `.claude/skills/` and wait for approval.
